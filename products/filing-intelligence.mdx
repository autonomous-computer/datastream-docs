Canonical events live at `/v1/events`. Use that catalog to prioritize a filing for review. Filing-intelligence extras (`/v1/filings/events`, `/v1/filings/diff`, `/v1/filings/transcripts`, `/v1/filings/guidance`) are currently unavailable and return `404` (`filings_intelligence_not_available`). Do not use them as a first-request dependency.

## Start with the live events catalog

```bash
curl -sS \
  -H "x-api-key: $SECAPI_API_KEY" \
  "https://api.secapi.ai/v1/events/enforcement?limit=25"
```

`/v1/events` is the live typed catalog (enforcement, auditor changes, officer changes, restatements, voting results, IPOs, and M&A). Each row is a source-linked review lead. Record the returned source URL, dates, and `requestId`, then open the cited filing or release.

| Method | Path | Job | Availability |
| --- | --- | --- | --- |
| `GET` | [`/v1/events/enforcement`](/api-reference/events/get-v1-events-enforcement) | Official SEC enforcement releases. | live |
| `GET` | [`/v1/events/ma`](/api-reference/events) | Filing-derived M&A signals. | live |
| `GET` | [`/v1/events/restatements`](/api-reference/events) | Restatement and non-reliance leads. | live |

See the [Events API](/products/enforcement) and the events reference family for the remaining live event routes. Filing-intelligence extras stay in the OpenAPI reference with `availability: gated`. They are not on this tour.

## Coverage, freshness, and source handling

Event rows point to evidence; they do not establish legal, accounting, or investment conclusions. A missing row does not establish that an event did not occur. Preserve any returned freshness or materialization fields, then retrieve the cited filing before quoting a passage or presenting a conclusion.
