Filing comparison

<Info>
Audience: application and coding agent.
</Info>

## Coverage and source scope

Compares a selected issuer filing with a prior-period or explicitly chosen counterpart and returns section-level change information. Any comparison is a review aid based on rendered filing text, not a determination of materiality or legal significance.

## Coverage and interpretation

The comparison is computed over rendered filing text between the selected filing and its prior-period or explicitly chosen counterpart. Treat it as a review aid and open the cited filings before relying on a change; a `422 insufficient_filings` means no comparable counterpart exists for that issuer and form, not that the endpoint is off.

## Canonical metadata

- `pairId`
- `ticker`
- `form`
- `base`
- `compare`
- `summary`
- `sections`
- `requestId`
- `traceparent`

## Example request

<RequestExample>
```bash
curl -X GET \
  -H "x-api-key: $SECAPI_API_KEY" \
  -H "secapi-version: 2026-03-19" \
  "https://api.secapi.ai/v1/filings/diff?ticker=AAPL&form=10-K"
```
</RequestExample>

## Give this prompt to your agent

<Prompt>
Use SEC API GET /v1/filings/diff with a ticker and form, preserve the selected filing citations, and treat its rendered-text comparison as a review aid rather than a materiality or legal-significance conclusion.
</Prompt>

## Failure posture

- a `404 filings_intelligence_not_available` on a filing comparison means filing intelligence is turned off for the account, not that the query matched nothing; it does not describe the endpoint's current state
- an empty `data` array from a filing comparison is a coverage gap for that issuer or window, not an outage
- preserve `requestId` and `traceparent` in logs and downstream reports
