Filing events

<Info>
Audience: application and coding agent.
</Info>

## Coverage and source scope

Lists persisted classifications from covered 8-K and 6-K filings for issuer- and date-bounded monitoring. Rows are derived from filing content; this is not a live market-news feed and does not enumerate each issuer event.

## Coverage and interpretation

Rows are classifications persisted from covered 8-K and 6-K filings, bounded by the issuer, form, category, and filed-date filters you pass. Preserve the filing citation on each row and verify a material event in the source filing before acting on it; a classification is a review aid, not a materiality determination.

## Canonical metadata

- `id`
- `ticker`
- `cik`
- `accessionNumber`
- `formType`
- `category`
- `summaryTitle`
- `requestId`
- `traceparent`

## Example request

<RequestExample>
```bash
curl -X GET \
  -H "x-api-key: $SECAPI_API_KEY" \
  -H "secapi-version: 2026-03-19" \
  "https://api.secapi.ai/v1/filings/events"
```
</RequestExample>

## Give this prompt to your agent

<Prompt>
Use SEC API GET /v1/filings/events with the documented form, category, issuer, and filed-date filters to create a bounded review queue, and verify material events in the cited filing. Rows are derived from filing content and are not a real-time market-news feed or a complete record of every issuer event.
</Prompt>

## Failure posture

- a `404 filings_intelligence_not_available` on the events feed means filing intelligence is turned off for the account, not that the query matched nothing; it does not describe the endpoint's current state
- an empty `data` array from the events feed is a coverage gap for that issuer or window, not an outage
- preserve `requestId` and `traceparent` in logs and downstream reports
