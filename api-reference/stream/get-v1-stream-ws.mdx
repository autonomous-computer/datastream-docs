WebSocket event stream

<Info>
Audience: application and coding agent.
</Info>

## Coverage and source scope

Upgrades an active stream subscription to a WebSocket connection. Supply that subscription's `stream_id` and authenticate with either a short-lived signed `ticket` from `POST /v1/stream/tickets` or the `x-api-key` header. Concurrent connections are capped by plan and are not separately billable; delivered events are billed in the same delivery-event family as stream polling and are idempotent per subscription and event.

## Canonical metadata

- `requestId`
- `traceparent`

## Example request

<RequestExample>
```bash
npx wscat -c "wss://api.secapi.ai/v1/stream/ws?stream_id=$SECAPI_STREAM_ID&ticket=$SECAPI_STREAM_TICKET" \
  -H "secapi-version: 2026-03-19"

# Mint the short-lived ticket first:
curl -X POST \
  -H "x-api-key: $SECAPI_API_KEY" \
  -H "secapi-version: 2026-03-19" \
  -H "content-type: application/json" \
  -d '{}' \
  "https://api.secapi.ai/v1/stream/tickets"

# Or authenticate the upgrade with an API key instead of a ticket:
npx wscat -c "wss://api.secapi.ai/v1/stream/ws?stream_id=$SECAPI_STREAM_ID" \
  -H "x-api-key: $SECAPI_API_KEY" \
  -H "secapi-version: 2026-03-19"
```
</RequestExample>

<Info>
Create and activate a WebSocket stream subscription first, then pass its `$SECAPI_STREAM_ID` and authenticate with either a short-lived `$SECAPI_STREAM_TICKET` minted with `POST /v1/stream/tickets` or an `x-api-key` upgrade header. Add an optional `cursor` to replay delivery records after that cursor. A ticket keeps a long-lived API key out of the browser-visible WebSocket URL.
</Info>
